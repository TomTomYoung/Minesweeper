# ズームとスクロールバーの仕様・実装分析

Phaser 3 の仕様に基づき、本プロジェクトにおけるズームとスクロールバーの実装詳細を整理したドキュメントです。

## 1. 座標系と配置

### World / Screen / Viewport
- **Screen (Canvas)**: ブラウザ上の表示領域（例: 1000x1000）。不変。
- **World**: ゲーム内の空間。盤面（Board）が配置される。
- **Viewport**: Screen に映し出される World の範囲。
    - 幅/高さ = `Screen / Zoom`

### 盤面の配置 (BoardManager)
- センタリング：盤面は **Screen の中央** に配置される計算（余白を2で割ってxだす）。
  ```javascript
  boardX = (ScreenW - BoardW) / 2
  ```
- **仕様確認**:
  - `boardX` が負の値になる（Screenより盤面が大きい）ことは Phaser の仕様上完全に問題ありません。
  - `camera.setBounds()` に負の値を設定することも正当です。

## 2. ズームの挙動

### 仕様：MidPoint 基準
- **誤解**: 「ズームの中心＝常に画面中央（固定）」
- **正解**: **「現在の Camera.midPoint（見ている中心）」を維持したまま拡縮**
    - 初期状態では `midPoint === 画面中央` ですが、パン操作などをすれば中心点は変わります。
    - ズーム操作によって `midPoint` 自体は移動しませんが、`worldView`（可視範囲）の矩形サイズが変化します。

## 3. スクロールバー計算の核心

### scrollX/Y vs worldView
Phaser の内部モデルにおける役割の違いが重要です。

| プロパティ | 意味と挙動 |
| :--- | :--- |
| `scrollX/Y` | **論理的な左上スクロール値**。<br>ズーム操作だけではこの値は変わりません（仕様）。これは「画面が映している範囲の左上」とは必ずしも一致しません。 |
| `zoom` | 拡縮倍率。 |
| `worldView` | **ズーム後に実際に画面に映っている矩形**。<br>`scrollX` に Viewport 補正を加えた「見た目の左上」を表します。 |

### 正しい実装指針
スクロールバー（UI）は「今どこが見えているか」を表示する機能です。
したがって、不変の `scrollX/Y` ではなく、**`camera.worldView.x / y`** を計算に使用するのが唯一の正解です。

```javascript
CurrentScrollX = camera.worldView.x; // ここが核心
```

## 4. 「左方向を映せない」問題（Clamp挙動）

現在の事象：**「ズームで画面は中央に寄るため、左方向を映すことができない」**

これは以下の条件で発生する **仕様通りの挙動（設計判断）** です。

- **条件**: `Bounds.width`（可動域） < `worldView.width`（見ている範囲）
- **挙動**: Phaser の Clamp 処理 (`maxScroll < minScroll` となる状態) により、カメラは強制的に **中央に固定** されます。

つまり、**「ズームアウトしすぎて（あるいは盤面が小さくて）、Bounds 全体が画面内に収まってしまっている」** 場合、左にスクロールできないのは正常です。
逆に、**「拡大して Bounds より狭い範囲を見ている」** のに左に行けない場合は、`Bounds` の計算自体（特に `left`）が間違っています。

## 5. 修正・確認アクション

1. **スクロールロジックの修正**:
   - `GameScrollController.js` で `cam.scrollX/Y` を参照している箇所をすべて `cam.worldView.x/y` (または `midPoint` からの逆算) に変更する。

2. **Bounds 検証**:
   - コンソールログで `Bounds.left` を確認する。これが正しく負の値（例: -500）になっているか。
   - `0` や `正の値` になっている場合、盤面配置認識にズレがあるため修正が必要。
