# Minesweeper 現行仕様

調査日: 2026-09-07 UTC
基準コミット: 30a29b7ab1fe4e0bb2cfa4fe4a2cafec8acabe08

## 1. プロジェクト概要

Phaser 3.60.0 を CDN から読み込んで動作する、ブラウザ向けマインスイーパーです。ビルド工程やパッケージ管理はなく、HTML とグローバル JavaScript クラスで構成されています。

入口の index.html から通常モードと RPG モードを選択し、それぞれ normal.html、rpg.html を開きます。両ページの実体はほぼ共通で、window.initialGameMode の値だけが異なります。

## 2. 実行方法

静的 HTTP サーバーの公開ディレクトリをリポジトリ直下にして index.html を開きます。Phaser と RexUI は外部 CDN へ接続できる環境が必要です。

現状は package.json、ビルドスクリプト、自動テスト、GitHub Actions がありません。

## 3. ゲームモード

### 3.1 通常モード

GameConfig.applyMode により、壁、お宝、階段、敵をすべて 0 にして通常のマインスイーパー盤面を生成します。

勝利条件は、地雷以外の全セルを開くことです。地雷を開くと敗北し、盤面全体が公開されます。

### 3.2 RPG モード

設定値に応じて地雷、宝、階段、敵、壁を生成します。現在のコード上では、階段を利用するには鍵の取得と全敵の撃破が必要です。階段は最初のクリックで公開され、公開済み階段をもう一度クリックしたときに利用判定が行われます。

次階層へ進むと level が 1 増え、GameScene が再起動します。2 階層目以降は、基準設定に対して地雷数が階層ごとに 10 パーセントずつ増加し、盤面総セル数の 30 パーセントで上限になります。宝の得点は階層ごとに 20 パーセントずつ増加します。

ただし、RPG モード固有の完成仕様と現行実装には差があります。詳細は PROGRESS.md に記載します。

## 4. 難易度

### 4.1 初級

行数 9、列数 9、地雷 10、壁クラスター 3、壁総数 10、宝 3、敵 2、階段 1、セルサイズ 40、宝得点 100 です。

### 4.2 中級

行数 16、列数 16、地雷 40、壁クラスター 5、壁総数 25、宝 5、敵 3、階段 1、セルサイズ 35、宝得点 100 です。

### 4.3 上級

行数 16、列数 30、地雷 99、壁クラスター 8、壁総数 40、宝 8、敵 5、階段 2、セルサイズ 30、宝得点 100 です。

### 4.4 カスタム設定

画面から行数、列数、地雷数、壁クラスター数、壁総数、宝数、階段数、壁クラスター自動公開を設定できます。行列は 5 から 30、地雷は 1 から 200 の範囲です。

敵数はカスタム画面に項目がなく、RPG モードでは GameConfig.currentConfig に残っている値が暗黙に使われます。これは意図が未確定の現行挙動です。

## 5. 盤面生成

初回クリックまでは全セルを空セルとして表示します。最初の左クリック時に、クリック地点と周囲 8 セルを安全地帯として実盤面を生成します。

現在の生成順は次の通りです。

1. 空盤面作成
2. 初回クリックを中心とする最大 3 行 3 列の安全地帯作成
3. 地雷配置
4. 宝と階段の配置
5. 敵配置
6. 壁配置
7. 隣接地雷数計算と数字セル化

地雷、宝、階段、敵、壁は安全地帯を避けます。宝と階段は、自身および周囲 8 セルに地雷がない候補へ配置されます。

重要な現行制約として、壁は最後に配置され、既存の地雷、宝、階段、敵を保護せずセル全体を WallLogicCell に置き換えます。このため、要求数どおりに先行配置された要素が消える場合があります。

## 6. セルと操作

### 6.1 左クリック

未公開セルを公開します。初回左クリックでは盤面を生成してからクリック位置を処理します。旗付きセルとゲーム終了後のセルは処理しません。

### 6.2 右クリック

未公開セルの旗を切り替えます。旗の最大数は設定上の地雷数です。初回左クリック前は旗を立てられません。

### 6.3 数字セル再クリック

公開済み数字セルの周囲の旗数が数字と一致すると、旗なしの未公開隣接セルを開きます。現行コードでは壁セルを対象から除外します。

### 6.4 空セルの自動展開

EmptyLogicCell が幅優先探索を行い、旗付き、地雷、公開済みセルを除外して連鎖公開します。空セルから隣接セルへ伝播し、数字セルは公開するだけで伝播を止めます。

現在のデータモデルは一座標一オブジェクトであり、既存 RPG 仕様書にあるベースセルと被覆セルの多層構造ではありません。

### 6.5 地雷

公開すると GAME_OVER を発行します。

### 6.6 壁

公開すると壁画像を表示します。autoRevealWallCluster が有効なら同一クラスターをすべて公開します。無効時は、公開済み壁を再クリックすると同一クラスターの上下左右の未公開壁を一段ずつ公開します。

ロジック上は旗を設定できますが、表示側 WallCell は旗表示を拒否します。モデルと表示の不一致があります。

### 6.7 宝

宝の内容は key、gold、sword です。最初に必ず key を一つ割り当て、残りを gold と sword の二択で割り当てます。

最初のクリックで宝を公開し、二回目のクリックで内容を取得します。gold は treasurePoints を加点し、key は階段の条件を満たし、sword は 50 点を加点します。

現行の敵処理は sword を要求も消費もしません。

### 6.8 敵

公開すると ENEMY_DEFEATED を発行し、撃破数を一つ増やして 50 点を加点します。現行実装では敵をクリックしても敗北せず、sword の所持判定もありません。

### 6.9 階段

最初のクリックで公開し、二回目のクリックで STAIRS_INTERACTED を発行します。鍵を持ち、かつ設定上の全敵を撃破済みなら NEXT_LEVEL を発行します。

## 7. 勝敗とスコア

地雷を開くと敗北です。

地雷でも壁でもない全セルが公開されると勝利です。勝利時には max(500 から経過秒数を引いた値, 0) と、残り旗数の 10 倍を加点します。

この通常勝利判定はモード分岐されていないため、RPG モードでも動作します。RPG の階段進行と競合する可能性があります。

ScoreManager の score と totalScore はどちらも同じ加点を受け、次階層に引き継がれます。二値の役割分担は未整理です。

## 8. UI とカメラ

画面は 800 行 600 ピクセルの Phaser キャンバスです。メニュー、ゲーム盤面、UI を別シーンに分けています。

UI は残り旗、経過時間、得点、総得点、新しいゲーム、メニューへ戻る操作を持ちます。

ズームスライダー、縦横スクロールバー、中クリック系のパン、移動可能な赤いフォーカスマーカーを備えています。カメラ移動範囲には固定値 2000 が使われており、盤面寸法との完全な連動は未完成です。

## 9. アーキテクチャ

GameConfig は難易度、モード、階層補正を管理します。

BoardGenerator と配置 Strategy 群は盤面を生成します。

BoardModel と LogicCell 群は Phaser 非依存の盤面状態とセル挙動を担当します。

GameSession はタイマー、旗、スコア、鍵、敵撃破数、勝敗を管理します。

GameScene と各 Controller、Manager は入力、ゲーム進行、盤面表示、カメラを仲介します。

UIScene と UI 部品群は情報表示と操作パネルを担当します。

Board と Cell 派生クラスはロジックセルを Phaser 表示へ変換します。

AudioManager と SaveManager は用意されていますが、ゲームフローへの統合は未完成です。

## 10. 仕様の優先順位

現在動作する挙動の確認には、この文書と src 以下のコードを使用します。

RPG の目標挙動を決める場合は docs/rpgモード仕様.md を参照します。ただし、その文書の被覆レイヤー、剣、つるはし、宝内容、階段条件の多くは未実装です。実装前に目標仕様として正式採用する範囲を決めてください。
