# Minesweeper 現行仕様と並行モード方針

## 1. プロジェクト概要

Phaser 3.60.0 を CDN から読み込んで動作する、ブラウザ向けマインスイーパーです。ビルド工程やnpm実行依存はなく、HTMLとグローバルJavaScriptクラスで構成されています。package.jsonはNode.js標準テストの実行用です。

入口の index.html から通常モードと RPG モードを選択し、それぞれ normal.html、rpg.html を開きます。両ページの実体はほぼ共通で、window.initialGameMode の値だけが異なります。

## 2. 実行方法

静的 HTTP サーバーの公開ディレクトリをリポジトリ直下にして index.html を開きます。Phaser と RexUI は外部 CDN へ接続できる環境が必要です。

`package.json` と `npm test`（Node.js標準の `node --test test/*.test.js`）があります。ビルドスクリプトとGitHub Actionsはありません。2026-10-16の修正後検証は37件成功です。Phaserは3.60.0固定、RexUIのCDN URLはバージョン固定されていません。

## 3. ゲームモード

### 3.1 通常モード

GameConfig.applyMode により、壁、お宝、階段、敵をすべて 0 にして通常のマインスイーパー盤面を生成します。

勝利条件は、地雷以外の全セルを開くことです。地雷を開くと敗北し、盤面全体が公開されます。

### 3.2 RPG モード

設定値に応じて地雷、宝、階段、敵、壁を生成します。現在のコード上では、階段を利用するには鍵の取得と全敵の撃破が必要です。階段は最初のクリックで公開され、公開済み階段をもう一度クリックしたときに利用判定が行われます。

階段条件成立時にNEXT_LEVELを一度だけ発行し、1.5秒の遷移待機に入ります。待機中はセル操作と経過時間を止め、GameSession.advanceLevelが階数を一つ増やし、階の得点を0にしてからGameSceneを再起動します。総得点だけを引き継ぎ、鍵・剣・撃破数・経過時間は毎階初期化します。各階に必ず鍵入りの宝を配置し、その階のアイテムだけで進行条件を満たせる構成にします。探索はエンドレスで、最終階・最終勝利は設けません。アイテム持ち越しを試す場合は別モードとします。2 階層目以降は、基準設定に対して地雷数が階層ごとに 10 パーセントずつ増加し、盤面総セル数の 30 パーセントで上限になります。宝の得点は階層ごとに 20 パーセントずつ増加します。

RPG_SIMPLEの剣は従来どおり取得フラグと50点の加点だけを持ち、敵撃破には要求も消費もしません。多層セル方式は別モードのRPG_LAYEREDとして並行開発します。多層方式の装備案をSIMPLEの不具合・未達仕様として扱いません。

### 3.3 並行開発するモード

#### CLASSIC

通常のマインスイーパーです。空白、数字、地雷、旗、初手安全、自動展開、数字再クリック、全安全セル公開による勝利を持ちます。各拡張モードを評価するための比較基準でもあります。

#### RPG_SIMPLE

現在の一座標一 LogicCell 方式を継承する軽量 RPG モードです。地雷、壁、敵、宝、階段は重複せず、それぞれ独立セルとして配置します。

全安全セル公開による通常勝利は使用せず、宝や装備を取得して階段へ到達することを中心にします。現在のRPGはGameModeRegistryによってRPG_SIMPLEへ正規化され、通常勝利を使わないRpgSimpleRuleSetで動きます。盤面・生成器はCLASSICと共通の単一セル実装です。

#### RPG_LAYERED

目標として、一座標にベースセルと被覆セルを保持する多層RPGモードを設けます。現行は識別子だけがあり、選択すると未実装エラーになります。

ベース層には空白、数字、地雷、宝、階段を置き、被覆層には壁、敵、または空を置きます。数字計算と自動展開はベース層を基準とし、手動操作は被覆層を優先します。

壁や敵を除去した後も、下のベースセルは未公開状態で残ります。剣、つるはしなどの装備を使う探索実験はこのモードで行います。

#### EXPERIMENTAL

目標として、仕様を安定させる前の変則ルールを試す実験モードを設けます。現行は識別子だけがあり、選択すると未実装エラーになります。敵や壁を数字へ含める、地雷を移動させる、時間経過で盤面を変化させるなど、CLASSIC、RPG_SIMPLE、RPG_LAYERED の既定ルールを変更する実験を隔離します。

有効性が確認できたルールは、既存モードのオプションまたは新しい独立モードへ昇格させます。

## 4. 難易度

### 4.1 初級

行数 9、列数 9、地雷 10、壁クラスター 3、壁総数 10、宝 3、敵 2、階段 1、セルサイズ 40、宝得点 100 です。

### 4.2 中級

行数 16、列数 16、地雷 40、壁クラスター 5、壁総数 25、宝 5、敵 3、階段 1、セルサイズ 35、宝得点 100 です。

### 4.3 上級

行数 16、列数 30、地雷 99、壁クラスター 8、壁総数 40、宝 8、敵 5、階段 2、セルサイズ 30、宝得点 100 です。

### 4.4 カスタム設定

画面から行数、列数、地雷数、壁クラスター数、壁総数、宝数、階段数、敵数、壁クラスター自動公開を設定できます。行列は5〜30、地雷は1〜200、敵は0〜30です。敵の初期値は2で、前回の難易度の値を引き継ぎません。

CLASSICの特殊セル数を0にした後で、実際に使う設定を検証します。全個数は非負整数、壁を置く場合はクラスターごとに1マス以上、置かない場合は壁とクラスターをともに0とします。RPGは宝と階段が各1個以上必要です。初手の最大3×3安全地帯を確保できる総数であることに加え、RPGでは後続階の地雷上限まで増えても総数が収まることを開始前に検証します。宝周辺の安全条件や壁の連結性による配置不能は生成時に処理します。

## 5. 盤面生成

初回クリックまでは全セルを空セルとして表示します。最初の左クリック時に、クリック地点と周囲 8 セルを安全地帯として実盤面を生成します。

現在の生成順は次の通りです。

1. 空盤面作成
2. 初回クリックを中心とする最大 3 行 3 列の安全地帯作成
3. 地雷配置
4. 宝と階段の配置
5. 敵配置
6. 壁配置
7. 隣接地雷数計算と数字セル化

地雷、宝、階段、敵、壁は安全地帯を避けます。宝と階段は、自身および周囲 8 セルに地雷がない候補へ配置されます。

PR #3で壁の既存セル上書きは修正済みです。WallPlacementStrategyは安全地帯・地雷・宝・階段・敵・既存壁を避け、上下左右に連結した各クラスターを配置します。各Strategyは要求数を満たせなければRangeErrorを送出し、成功時の実数を盤面配列の非列挙placementCountsに格納します。GameSessionは実数を残り旗・必要敵数へ反映します。

生成乱数はMath.randomで、正式なseed注入APIはありません。配置不能RangeErrorの場合は盤面全体を最大32回生成し直します。要求個数を減らしたり、途中までの盤面を採用したりしません。上限まで失敗した場合は初手待ちのまま説明を表示し、再クリックによる再生成やメニューでの設定変更ができます。セル総数だけでなく宝／階段の周辺安全条件と壁の連結性が配置可否に影響するため、事前検証に通った全設定で生成成功を保証するものではありません。

## 6. セルと操作

### 6.1 左クリック

未公開セルを公開します。初回左クリックでは盤面を生成してからクリック位置を処理します。旗付きセル、ゲーム終了後、次階層への遷移待機中のセルは処理しません。

### 6.2 右クリック

未公開セルの旗を切り替えます。旗の最大数は設定上の地雷数です。初回左クリック前は旗を立てられません。

### 6.3 数字セル再クリック

公開済み数字セルの周囲の旗数が数字と一致すると、旗なしの未公開隣接セルを開きます。現行コードでは壁セルを対象から除外します。

### 6.4 空セルの自動展開

EmptyLogicCell が幅優先探索を行い、旗付き、地雷、公開済みセルを除外して連鎖公開します。空セルから隣接セルへ伝播し、数字セルは公開するだけで伝播を止めます。特殊セルもisRevealed/stateを直接変更し、公開だけを行います。自動公開された敵は未撃破のまま残り、プレイヤーがその敵をクリックすると撃破します。数字再クリックによる敵の自動公開も同じ扱いです。

現在のデータモデルは一座標一オブジェクトであり、既存 RPG 仕様書にあるベースセルと被覆セルの多層構造ではありません。

### 6.5 地雷

公開すると GAME_OVER を発行します。

### 6.6 壁

公開すると壁画像を表示します。autoRevealWallCluster が有効なら同一クラスターをすべて公開します。無効時は、公開済み壁を再クリックすると同一クラスターの上下左右の未公開壁を一段ずつ公開します。

未公開の壁にも旗を設定でき、画面にも表示します。クラスターの自動公開・隣接壁の公開は旗付きセルを除外し、旗を取り外せる状態を保ちます。

### 6.7 宝

宝の内容は key、gold、sword です。最初に必ず key を一つ割り当て、残りを gold と sword の二択で割り当てます。

最初のクリックで宝を公開し、二回目のクリックで内容を取得します。gold は treasurePoints を加点し、key は階段の条件を満たし、swordはhasSwordをtrueにして50点を加点します。

現行の敵処理は sword を要求も消費もしません。

### 6.8 敵

敵を直接クリックするとENEMY_DEFEATEDを一度だけ発行し、撃破数を一つ増やして50点を加点します。空白連鎖・数字再クリックによる自動公開は公開だけに留め、後からその敵をクリックすると同じ撃破処理を行います。撃破済みはstate 2で保持し、表示を薄くして再加点を防ぎます。RPG_SIMPLEでは剣を要求も消費もせず、敵クリックによる敗北もありません。

### 6.9 階段

最初のクリックで公開し、二回目のクリックで STAIRS_INTERACTED を発行します。鍵を持ち、かつ実配置数の全敵を撃破済みならNEXT_LEVELを発行します。条件不成立時はKEY_REQUIREDまたはENEMIES_REMAINをprogressionとして返し、画面に鍵不足または残り敵数を表示します。条件成立した階段は点滅で利用可能を示します。

## 7. 勝敗とスコア

地雷を開くと敗北です。

CLASSICで地雷でも壁でもない全セルが公開されると勝利です。通常のCLASSIC設定では壁は0です。勝利時には max(500 から経過秒数を引いた値, 0) と、残り旗数の 10 倍を加点します。

通常勝利判定はRuleSet.shouldCheckClassicWinへ委譲済みで、RPG_SIMPLEでは呼びません。勝利ボーナスの一回性も既存テストで確認済みです。RPG_SIMPLEはエンドレスで、最終階・最終勝利は仕様として設けません。

scoreはその階の得点で、次階層に進む際に0へリセットします。totalScoreは同じ加点を累計し、階をまたいで保持します。「新しいゲーム」では1階・両得点0から開始し、持ち物も初期化します。

## 8. UI とカメラ

画面は 800×600ピクセルの Phaser キャンバスです。メニュー、ゲーム盤面、UI を別シーンに分けています。

UIは残り旗、経過時間、階得点、総得点、モード、階数、鍵・剣の所持、敵撃破数を表示します。新しいゲーム、メニューへ戻る操作を持ちます。宝の公開時には加点通知を出さず、取得時に内容に応じた得点・通知・取得済み画像へ更新します。

ズームスライダー、縦横スクロールバー、中クリック系のパン、移動可能な赤いフォーカスマーカーを備えています。ホイールとスライダーのズームは同じ処理を使い、選んだフォーカス位置を固定して拡縮します。Phaserカメラの中央原点を計算に含め、マーカーの画面位置・大きさも補正します。カメラ移動範囲には固定値2000が使われており、盤面寸法との完全な連動は未完成です。

## 9. アーキテクチャ

GameConfig は難易度、モード、階層補正を管理します。

BoardGenerator と配置 Strategy 群は盤面を生成します。

BoardModel と LogicCell 群は Phaser 非依存の盤面状態とセル挙動を担当します。

GameSession はタイマー、旗、スコア、鍵、敵撃破数、勝敗を管理します。

GameScene と各 Controller、Manager は入力、ゲーム進行、盤面表示、カメラを仲介します。

UIScene と UI 部品群は情報表示と操作パネルを担当します。

Board と Cell 派生クラスはロジックセルを Phaser 表示へ変換します。

AudioManager と SaveManager は用意されていますが、ゲームフローへの統合は未完成です。

## 10. モード分離の設計原則

HTML、UI、カメラ、入力処理をモードごとに全面複製しません。モード定義が盤面モデル、盤面生成器、ルールセットを選択する構成にします。

各モードは、盤面生成、セル操作、旗操作、進行判定、全公開、表示用セル状態取得について共通インターフェースを実装します。

内部データが単一セルでも多層セルでも、表示側へは座標、公開状態、旗状態、ベース表示、被覆表示、数字、操作状態を含む共通 ViewModel を返します。GameScene と Board は特定モードの内部構造を直接参照しません。

現行は通常勝利の有効／無効と階段条件をモード別RuleSetへ委譲しています。地雷敗北と通常勝利の全セル走査・加点はGameSessionに残ります。勝利・敗北・次階層・継続のすべてをRuleSetへ分離し、共通ViewModelへ統一することは後続の目標です。

乱数生成器または seed を注入できる構成にし、同一 seed の盤面を異なるモードで比較できるようにします。

## 11. 仕様の位置づけ

現在動作する挙動の確認には、この文書と src 以下のコードを使用します。

docs/rpgモード仕様.md の被覆レイヤー、剣、つるはし、宝内容、階段条件は RPG_LAYERED の目標案として扱います。

現在の一座標一 LogicCell 方式は誤実装として削除せず、RPG_SIMPLE の基礎として保持します。

本プロジェクトは好奇心に基づく試作であり、モード間でルールが異なることを許容します。ただし、同じモード内の仕様と実装の不一致、および共通基盤の不具合は解消対象です。

## 12. 実装の追跡先と保存の範囲

入口は `index.html` → `normal.html`／`rpg.html` → `main.js` → BootScene → MenuScene → GameScene／UISceneです。HTMLのscript順でグローバルクラスを読み込むため、ES Modulesやbundler前提ではありません。

- 設定と階層補正: [GameConfig.js](../src/utils/GameConfig.js)。通常ページはSTANDARD、RPGページはRPGを渡し、RegistryがCLASSIC／RPG_SIMPLEへ正規化します。
- ルール選択: [GameModeRegistry.js](../src/logic/modes/GameModeRegistry.js)。未実装／不明モードはRangeErrorです。
- 生成: [BoardGenerator.js](../src/logic/BoardGenerator.js) と `src/logic/generator/strategies/`。
- 状態: [BoardModel.js](../src/logic/BoardModel.js) の2次元配列と `src/logic/cells/`。stateは0=隠蔽、1=公開、2=取得等の操作済みです。
- 進行: [GameSession.js](../src/logic/GameSession.js)、[GameFlowController.js](../src/game/controllers/GameFlowController.js)、[GameScene.js](../src/scenes/GameScene.js)。scene再起動ごとに鍵・剣・撃破数を初期化します。
- 表示同期: [Board.js](../src/objects/Board.js) と `src/objects/special/`。公開・旗・state・treasureContentをupdateStateへ渡し、宝取得と敵撃破を表示へ同期します。

SaveManagerはクラスとして存在しますが、進行保存・復元ボタンや自動保存へ接続されていません。AudioManagerも主要フローに統合されておらず、BootSceneは画像9点だけをロードします。音声ファイルのpreloadは除去済みです。サーバーAPI、通信対戦、JSONファイル入出力はありません。

本書の現行挙動と既知課題を対象にコード・Node.jsテストを確認しました。ブラウザ上の描画、入力、CDN取得、音声再生は今回未検証です。
