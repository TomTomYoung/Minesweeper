### 3.2 壁による上書き（防止・配置不足エラー・実数返却は実装済み）

短期修正として、WallPlacementStrategy の開始地点と展開先で isMine、isEnemy、isTreasure、isStairs を確認し、占有セルを置換しないようにします。

### 3.3 モード別勝利判定（RuleSetへの分離は実装済み）

GameSession へ mode を明示的に渡すか config に mode を含めます。

STANDARD は地雷以外の全セル公開で勝利します。

RPG は原則として通常勝利判定を行わず、鍵取得、必要な敵撃破、階段利用で次階層へ進みます。最終的なゲーム終了条件が必要なら、仕様を別途確定します。

完了条件は、RPG で盤面を広く公開しても通常勝利にならず、条件を満たした階段操作だけが NEXT_LEVEL を発行することです。

### 3.4 モード境界（Registryは実装済み、共通ViewModelは未実装）

単一セル方式と多層セル方式は一本化しません。

CLASSIC、RPG_SIMPLE、RPG_LAYERED、EXPERIMENTAL のモード定義を設け、各定義から BoardModel、BoardGenerator、RuleSet を選択できるようにします。

各 BoardModel は、盤面生成、左操作、旗操作、進行判定、全公開、表示用状態取得について共通インターフェースを実装してください。

表示側には内部クラスを直接渡さず、座標、公開、旗、ベース表示、被覆表示、数字、操作状態からなる共通 ViewModel を渡します。

完了条件は、CLASSIC と既存 RPG が同じ GameScene と Board を使いながら、別の RuleSet で動作することです。

### 3.5 RPG_SIMPLE（現行単一セル方式を登録済み）

現行の一座標一 LogicCell 方式を RPG_SIMPLE として残します。

壁、敵、宝、階段は重複しない独立セルです。WallPlacementStrategy が他セルを上書きする問題を直し、全要素の配置数を検証します。

RPG_SIMPLE では全安全セル公開による通常勝利を無効にし、階段利用で次階層へ進みます。

### 3.6 RPG_LAYERED を新設する

docs/rpgモード仕様.md の多層案は RPG_LAYERED として実装します。

セルは少なくとも base、cover、revealed、flagged を持ちます。地雷数と自動展開は base を参照し、手動操作は cover を優先します。

最初は壁だけを cover として実装し、テスト後に敵、剣、つるはしを追加します。

完了条件は、壁または敵の下に地雷、数字、空白、宝、階段を保持でき、被覆除去後に下層が未公開で残ることです。
