## 3. P0 修正指示

### 3.1 起動資産を整合させる

BootScene のロード一覧と assets 以下を一致させてください。

音声をまだ採用しない場合は、存在しない音声の preload を一時的に外し、音声なしでも正常起動する状態を先に作ります。採用する場合は権利の明確な音源を追加し、出典とライセンスを記録します。

enemy、key、sword のテクスチャは使用箇所とロード名を統一してください。

完了条件は、両モードで初期ロード時の 404 と未登録テクスチャ参照がないことです。

### 3.2 壁による上書きを止める

短期修正として、WallPlacementStrategy の開始地点と展開先で isMine、isEnemy、isTreasure、isStairs を確認し、占有セルを置換しないようにします。

配置不能時は黙って不足させず、実配置数を返し、GameSession が実数を把握できるようにするか、設定を事前検証してください。

中長期的に被覆レイヤーを正式採用するなら、この短期修正の後で別 PR としてモデルを再設計します。

完了条件は、生成後の地雷、宝、敵、階段、壁の実数が設定と一致し、安全地帯に特殊セルがないことです。

### 3.3 モード別勝利判定に分ける

GameSession へ mode を明示的に渡すか config に mode を含めます。

STANDARD は地雷以外の全セル公開で勝利します。

RPG は原則として通常勝利判定を行わず、鍵取得、必要な敵撃破、階段利用で次階層へ進みます。最終的なゲーム終了条件が必要なら、仕様を別途確定します。

完了条件は、RPG で盤面を広く公開しても通常勝利にならず、条件を満たした階段操作だけが NEXT_LEVEL を発行することです。

### 3.4 モード境界を導入する

単一セル方式と多層セル方式は一本化しません。

CLASSIC、RPG_SIMPLE、RPG_LAYERED、EXPERIMENTAL のモード定義を設け、各定義から BoardModel、BoardGenerator、RuleSet を選択できるようにします。

各 BoardModel は、盤面生成、左操作、旗操作、進行判定、全公開、表示用状態取得について共通インターフェースを実装してください。

表示側には内部クラスを直接渡さず、座標、公開、旗、ベース表示、被覆表示、数字、操作状態からなる共通 ViewModel を渡します。

完了条件は、CLASSIC と既存 RPG が同じ GameScene と Board を使いながら、別の RuleSet で動作することです。

### 3.5 RPG_SIMPLE を保存する

現行の一座標一 LogicCell 方式を RPG_SIMPLE として残します。

壁、敵、宝、階段は重複しない独立セルです。WallPlacementStrategy が他セルを上書きする問題を直し、全要素の配置数を検証します。

RPG_SIMPLE では全安全セル公開による通常勝利を無効にし、階段利用で次階層へ進みます。

### 3.6 RPG_LAYERED を新設する

docs/rpgモード仕様.md の多層案は RPG_LAYERED として実装します。

セルは少なくとも base、cover、revealed、flagged を持ちます。地雷数と自動展開は base を参照し、手動操作は cover を優先します。

最初は壁だけを cover として実装し、テスト後に敵、剣、つるはしを追加します。

完了条件は、壁または敵の下に地雷、数字、空白、宝、階段を保持でき、被覆除去後に下層が未公開で残ることです。

## 5. テスト計画

### 5.1 BoardGenerator

1. 初回クリックの最大 3 行 3 列に地雷と特殊セルがない
2. 各種類の実配置数が設定値と一致する
3. 宝と階段の周囲に地雷がない
4. 数字が周囲 8 セルの地雷数と一致する
5. 高密度設定でも無限ループしない
6. 配置不能設定を明示的に失敗させる

乱数注入または seed 対応を追加し、再現可能なテストにしてください。

### 5.2 BoardModel と LogicCell

1. 空セルの BFS が地雷と旗を開かない
2. 数字セルの周囲一括公開が旗数一致時だけ動く
3. 誤った旗配置からの一括公開で地雷を開けば GAME_OVER になる
4. 旗数上限が守られる
5. 宝が公開、取得済みへ遷移する
6. 鍵、剣、金のイベントが一回だけ出る
7. 敵と壁の相互作用が採用仕様どおりである
8. revealAll が全種類を表示状態にする

### 5.3 GameSession

1. 初回クリックまでタイマーが進まない
2. 地雷で敗北する
3. STANDARD だけが全安全セル公開で勝利する
4. 勝利ボーナスが一回だけ入る
5. RPG の階段条件が鍵と敵撃破数を正しく見る
6. 次階層で level、score、totalScore、設定補正が意図どおり引き継がれる

### 5.4 ブラウザ統合

1. index.html から両モードへ移動できる
2. 三難易度とカスタムが開始できる
3. 右クリックメニューが抑止され旗が切り替わる
4. ズーム、パン、スクロールバーが同期する
5. 新しいゲームとメニューへ戻る操作を繰り返してもイベントが重複しない
6. コンソールエラーと Network 404 がない

## 6. 作業単位の推奨

一つの PR に一つの目的を持たせてください。

最初の PR は起動資産と最低限の smoke test、次の PR はモード定義と RuleSet 境界、その次は現行 RPG の RPG_SIMPLE 化が適切です。

RPG_LAYERED は、データ型、生成器、壁被覆、敵被覆、装備の順に専用 PR を分けます。EXPERIMENTAL は共通基盤と seed 対応が完成してから開始します。

各 PR 本文には、変更理由、変更範囲、手動確認手順、自動テスト結果、未解決事項を記載してください。

## 7. 変更時の注意

1. normal.html と rpg.html の script 読み込み順はクラスの依存順です。片方だけ直さないでください。
2. ロジック層へ Phaser API を持ち込まないでください。
3. BoardModel の状態と Board の表示状態を直接別々に変更せず、同期経路を一本化してください。
4. 生成 Strategy の置換順はゲームルールそのものです。順序変更だけで済ませず、配置後の不変条件をテストしてください。
5. backup と trash はすぐ削除せず、現行コードとの差分と必要性を確認してから別 PR で整理してください。
6. docs 以下の古い資料を更新する場合も、doc 以下の三文書と矛盾しないよう同じ PR で更新してください。
