# RPG_SIMPLE 安定化修正記録

更新日: 2026-10-16
修正開始時の main: `a17ee73a3e21d2ebbb5c6fde4630e2d9c88f9000`

## 確定したルール

1. 空白連鎖や数字再クリックで自動公開された敵は、公開だけを行う。後からその敵をクリックすると撃破する。未公開の敵を直接クリックする場合は、従来どおりその操作で撃破する。
2. RPG_SIMPLEの剣は変更しない。取得時に所持フラグと50点を得る。敵撃破には不要で、消費もしない。
3. アイテムを次階層へ持ち越さない。毎階に鍵を供給し、その階のアイテムで進行条件を満たせるようにする。持ち越しを試す場合は別モードで扱う。
4. 階得点は階ごとにリセットする。総得点は一回の探索全体の累計とする。
5. 探索はエンドレス。最終階と最終勝利は設けない。地雷による敗北は維持する。

階段の条件は、その階の鍵を取得し、その階の全敵を撃破すること。RPG_LAYEREDの装備・戦闘ルールは別途設計する。

## 修正した問題

### 敵・進行・得点

- 自動公開された敵が操作不能となるM-01を修正。敵の公開と撃破を分け、state 2で撃破済みを保持する。連打による二重撃破・加点を防ぐ。
- 数字再クリックからの自動公開も上記ルールに統一する。複数の撃破イベントを受け取った場合は個別に数える。
- 階層更新がUI同期で旧値に戻るM-02、遷移を重複予約できるM-03を修正。GameSessionを階数の正本とし、遷移予約中は入力とタイマーを停止する。
- 1.5秒後に階数を一度だけ増やし、階得点を0にしてからSceneを再起動する。総得点だけを引き継ぎ、鍵・剣・撃破数・経過時間は初期化する。
- 「新しいゲーム」は一度だけ再起動し、1階・階得点0・総得点0から始める。予約済み遷移と遅延入力を取り消す。

### 生成・設定

- M-04の生成例外をGameSessionで捕捉し、初手待ちの盤面を維持して説明を表示する。再クリックで再生成でき、メニューから設定を変更できる。
- 配置が失敗した場合は盤面全体を最大32回再生成する。個数を減らす処理は行わず、全試行失敗は明示する。
- カスタム画面に敵数を追加する。未指定時は初級の2体を用い、前回難易度の敵数を引き継がない。
- モード適用後の実効設定を検証する。CLASSICで使わないRPG項目が通常盤面の開始を妨げないようにする。
- RPGの宝0・階段0、壁総数とクラスター数の不整合、敵を含めた容量超過を拒否する。後続階で地雷が上限まで増えた場合も安全地帯と全特殊セルが収まるか検証する。
- 宝周辺の安全条件や壁の連結性による配置不能は引き続き生成時に判断する。開始前の検証だけで、すべての設定の生成成功を保証するものではない。

### 表示・入力・寿命

- BoardからCellへ公開・旗・state・宝内容を同じ経路で同期する。宝の取得済み画像と敵の撃破済み表示を更新する。
- 宝を見せただけで出ていた固定の加点表示を除き、実際の取得イベントTREASURE_GOLDに合わせて正しい点数を通知する。
- 壁の旗を表示する。クラスター公開時は旗付き壁を除外し、後から旗を外せる状態を保つ。
- 勝敗確定の全公開では旗を消して実際のセルを表示する。取得済み・撃破済みstate 2は維持する。
- HUDにモード・階数・鍵・剣・敵撃破数を追加する。階段の利用可能状態と、鍵不足・残り敵数を表示する。
- UISceneからの初期値要求に応答し、最初の通知を取り逃しても正しい旗数・得点・カメラ状態を表示する。
- Scene終了時に自身の購読だけを解除する。共有イベントの全購読を消さず、他の利用者を保持する。盤面と遅延入力も終了処理に接続する。
- Phaserカメラの中央原点をズーム計算へ含め、ホイールとスライダーを同期する。マーカーはズームに対して画面位置・大きさを保つ。

Controller→SceneのUI同期→遅延遷移の順序も試験した。Phaser依存部分にはスタブを用いており、ブラウザでの描画・実入力は検証していない。実行環境の制約によりChromiumをsandbox有効のまま起動できなかったため、ブラウザ回帰試験は未完了として扱う。

全JavaScriptの構文チェックと `git diff --check` も実施する。静的配信・テスト方法は [README.md](./README.md) を参照。
