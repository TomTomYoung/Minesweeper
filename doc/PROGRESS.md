## 1. 総合判定

通常モードは中核ロジックと画面構成が実装済みです。最小限のロジックテストは追加しましたが、実ブラウザでの回帰確認と網羅的な自動テストはありません。

RPG モードは要素の表示と一部イベントが動く試作段階です。既存の RPG 仕様書が要求する多層セル、装備消費、敵との危険な相互作用、階段中心の勝利条件には達していません。

プロジェクト全体としては、機能追加より先に「起動を安定させる」「現行ロジックをテスト可能にする」「モードごとに盤面モデルとルールを差し替えられるようにする」の三点が必要です。

単一セル方式と多層セル方式のどちらか一方へ統一する必要はありません。現在の方式は RPG_SIMPLE として保持し、多層方式は RPG_LAYERED として別に追加する方針が確定しました。

## 3. 部分実装

### 3.1 RPG モード

宝、鍵、剣、敵、壁、階段の名前とイベントはありますが、設計書どおりには連携していません。

鍵は階段条件に使われます。剣は取得時に 50 点を加えるだけで、敵との戦闘に使われません。つるはしはデータにも UI にもありません。敵はクリックするだけで必ず撃破できます。

### 3.2 宝の二段階操作

ロジックは公開と取得の二段階ですが、BoardManager.updateBoardUI は公開状態と旗を中心に同期し、state 2 と treasureContent の表示更新を十分に反映しません。

### 3.3 スコア通知

GameSession は TREASURE_GOLD を処理して得点を加えますが、GameFlowController は TREASURE という別名を待っています。このため、得点は増えても宝発見メッセージと効果音が発火しません。

### 3.4 保存と音声

SaveManager と AudioManager はクラスだけ存在し、主要シーンで生成、復元、保存されていません。

BootScene は click、explosion、treasure の音声を assets/sounds から読み込もうとしますが、リポジトリのツリーに assets/sounds がありません。

### 3.5 カメラと UI

基本部品は実装されていますが、パン範囲が固定値 2000 で、盤面サイズと画面サイズから導出されていません。GameScene と UIScene のイベント寿命も手動整理が多く、再起動時の確認が必要です。

## 5. 既知の重要不具合とリスク

### P0 起動資産の不整合

存在しない音声の preload は停止し、enemy、key、sword を含む使用画像を BootScene でロードするよう修正済みです。音声は素材の出典とライセンスを確定してから正式採用します。

静的な資産存在テストは追加済みです。通常モードと RPG モードについて、実ブラウザのコンソールと Network に 404 がないことの継続的な統合確認はまだ必要です。

### P0 壁配置が既存セルを上書きする

WallPlacementStrategy は全特殊セルと安全地帯を占有不可として扱うよう修正済みです。全配置 Strategy は要求数を満たせない場合に明示的な RangeError を投げ、生成結果の実配置数は placementCounts として GameSession が参照します。

高密度かつ複数クラスターの設定では、空きセル数が足りていても連結領域が不足すれば明示的に生成失敗となります。カスタム設定画面での事前検証とユーザー向けエラー表示は今後追加が必要です。

### P0 RPG と通常勝利条件の競合

GameSession は明示的な mode を受け取り、通常の全安全セル公開による勝利は STANDARD だけで判定するよう修正済みです。RPG は鍵を取得し、必要数の敵を倒した後の階段操作だけで NEXT_LEVEL を発行します。

現時点のモード名は既存互換の STANDARD/RPG のままです。CLASSIC/RPG_SIMPLE を含む正式なモード境界と RuleSet 化は次の P0 作業として残っています。

### P0 モード境界が未実装

GameModeRegistry を追加し、既存名 STANDARD/RPG を CLASSIC/RPG_SIMPLE へ正規化したうえで、各 ModeDefinition から BoardModel、BoardGenerator、RuleSet を選択する最初の境界を実装しました。

現時点では CLASSIC と RPG_SIMPLE が既存の単一セル BoardModel/BoardGenerator を共有し、進行条件だけを別 RuleSet としています。RPG_LAYERED と EXPERIMENTAL は識別子のみ定義し、未実装モードを選択した場合は明示的に失敗します。専用 BoardModel/Generator と共通 ViewModel は後続作業です。

### P1 カスタム RPG の敵数が暗黙値

カスタム画面に enemies がなく、GameConfig.updateConfig のマージによって直前設定の敵数が残ります。バリデーションの特殊セル合計にも敵が含まれません。

### P1 宝イベント名の不一致

ロジックの TREASURE_GOLD と表示側の TREASURE が一致しません。

### P1 壁の旗状態がモデルと表示で不一致

WallLogicCell は通常の toggleFlag を使用できる一方、WallCell.toggleFlag は常に false を返します。

### P1 宝の取得済み状態が表示へ同期されない

表示更新が cellData.state と treasureContent を継続的に渡していません。

### P1 新しいゲーム操作の再起動重複

UIScene.restartGame は GameScene.restartGame を連続して二回呼び出しています。二重再起動やイベント残留の原因になり得ます。

### P2 ソースコメントの文字化け

BoardGenerator.js の日本語コメントが文字化けしています。実行ロジックへの直接影響はありませんが、保守性を下げています。

### P2 不要物と重複資産

backup と trash に旧コードや一時スクリプトが残っています。jpg と png で実体が同じ資産もあります。削除は履歴確認後に別作業として行うべきです。

## 6. 確定した開発方針

1. CLASSIC を比較基準として維持します。
2. 現在の単一セル RPG を RPG_SIMPLE として保存します。
3. ベース層と被覆層を持つ方式を RPG_LAYERED として新設します。
4. 仕様未確定の変則ルールは EXPERIMENTAL に隔離します。
5. UI、カメラ、入力、イベント配送は可能な範囲で共有します。
6. BoardModel、BoardGenerator、RuleSet はモードごとに交換可能にします。
7. 表示側へ渡すセル状態は共通 ViewModel に揃えます。
8. seed 対応を行い、同一条件でモードを比較できるようにします。
9. モードごとに所要時間、クリック数、旗数、死亡原因、到達階層、装備使用数、詰み発生を記録できるようにします。

## 7. モード別進捗

### CLASSIC

中核機能は実装済みです。起動資産の整合、回帰試験、自動テストが未完了です。

### RPG_SIMPLE

現在の RPG 実装が原型です。通常勝利条件との分離、壁上書き防止、宝イベントと表示同期、装備ルールの単一セル向け整理が必要です。

### RPG_LAYERED

未実装です。base と cover を持つ盤面データ、生成器、操作優先順位、被覆除去、共通 ViewModel が必要です。

### EXPERIMENTAL

未実装です。先に共通モード境界と seed 対応を用意してから追加します。
