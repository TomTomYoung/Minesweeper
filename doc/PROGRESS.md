## 5. 既知の重要不具合とリスク

### P0 起動資産の不整合

存在しない音声の preload は停止し、enemy、key、sword を含む使用画像を BootScene でロードするよう修正済みです。音声は素材の出典とライセンスを確定してから正式採用します。

静的な資産存在テストは追加済みです。通常モードと RPG モードについて、実ブラウザのコンソールと Network に 404 がないことの継続的な統合確認はまだ必要です。

### P0 壁配置が既存セルを上書きする

WallPlacementStrategy は全特殊セルと安全地帯を占有不可として扱うよう修正済みです。全配置 Strategy は要求数を満たせない場合に明示的な RangeError を投げ、生成結果の実配置数は placementCounts として GameSession が参照します。

高密度かつ複数クラスターの設定では、空きセル数が足りていても連結領域が不足すれば明示的に生成失敗となります。カスタム設定画面での事前検証とユーザー向けエラー表示は今後追加が必要です。

### P0 RPG と通常勝利条件の競合

GameSession は明示的な mode を受け取り、通常の全安全セル公開による勝利は STANDARD だけで判定するよう修正済みです。RPGは鍵を取得し、必要数の敵を倒した後の階段操作だけでNEXT_LEVELを発行します。イベント発行後の実際の階層更新にはM-02の不具合が残っています。

HTML入力名はSTANDARD/RPGを維持し、RegistryでCLASSIC/RPG_SIMPLEへ正規化しています。RuleSetによる通常勝利の分離と階段条件判定は完了しています。ただしイベント発行後の実際の階層遷移にはM-02／M-03が残ります。

### 旧P0 モード境界の導入済み範囲

GameModeRegistry を追加し、既存名 STANDARD/RPG を CLASSIC/RPG_SIMPLE へ正規化したうえで、各 ModeDefinition から BoardModel、BoardGenerator、RuleSet を選択する最初の境界を実装しました。

現時点では CLASSIC と RPG_SIMPLE が既存の単一セル BoardModel/BoardGenerator を共有し、進行条件だけを別 RuleSet としています。RPG_LAYERED と EXPERIMENTAL は識別子のみ定義し、未実装モードを選択した場合は明示的に失敗します。専用 BoardModel/Generator と共通 ViewModel は後続作業です。

### P1 カスタム RPG の敵数が暗黙値

カスタム画面に enemies がなく、GameConfig.updateConfig のマージによって直前設定の敵数が残ります。バリデーションの特殊セル合計にも敵が含まれません。

### P1 宝イベント名の不一致

ロジックの TREASURE_GOLD と表示側の TREASURE が一致しません。

### P1 壁の旗状態がモデルと表示で不一致

### P1 宝の取得済み状態が表示へ同期されない

表示更新が cellData.state と treasureContent を継続的に渡していません。

### P1 新しいゲーム操作の再起動重複

UIScene.restartGame は GameScene.restartGame を連続して二回呼び出しています。二重再起動やイベント残留の原因になり得ます。

### 旧P2 BoardGeneratorのコメント

現行BoardGenerator.jsは英語コメントに整理済みで、以前の文字化け記述は現在の課題から外します。

### P2 不要物と重複資産

## 10. 2026-10-16追加調査で確認した未修正課題

ここは現時点の再開優先順位です。旧P0の解消済み事項と区別します。一時診断は既存14テストに追加していません。今回の変更は文書だけです。

### M-01 / P0: 自動展開した敵を倒せず、階段が永久に解放されない

`EmptyLogicCell.reveal` のBFSは隣接特殊セルを直接公開し、`EnemyLogicCell.reveal` を呼びません。公開済み敵のinteractは基底クラスの空処理です。

最小診断盤面を1行3列の `[Empty, Enemy, Stairs]` とし、RPGの必要敵数1、鍵ありでEmptyを開くと、敵は公開済み・撃破数0のままです。敵を再クリックしてもイベントは空、階段はENEMIES_REMAINを返しました。実際のランダム生成でも空白と敵が隣接する構成を禁止していません。

### M-02 / P0: 次階層のlevelを直後に旧値で上書きする

`GameScene.handleResult` → `GameFlowController.processResult` → `goToNextLevel` で `gameData.level++` を行い、1.5秒後のrestartを予約します。しかし同じhandleResultの末尾で `updateUI` が `gameSession.level` をgameData.levelへ代入します。session側のlevelは増えていません。

Controllerを時間予約のスタブで実行するとlevelは1→2、実コードと同じupdateUI代入後は1へ戻りました。これは処理順と代入の診断で、Phaser画面を実際に遷移させた結果ではありません。

### M-03 / P1: 次階層イベントを何度でも発行できる

条件成立済みの公開階段を2回操作すると、それぞれSTAIRS_INTERACTEDとNEXT_LEVELを返します。セッションには遷移予約済み状態がなく、Controllerも重複予約を防ぎません。M-02修正時に同時にガードし、1操作で1遷移とします。

### M-04 / P1: 配置不能エラーと進行不能なカスタム設定の扱い

生成器はRangeErrorを明示するようになりましたが、初手クリックのInputController／GameSessionに捕捉と復帰UIがありません。カスタム検証にはenemiesが含まれず、宝0を許可する一方、RPGの階段は常に鍵必須です。宝0では鍵を生成できず先へ進めません。高密度盤面や壁の連結領域不足も別途検証が必要です。

### 継続するP1・P2
